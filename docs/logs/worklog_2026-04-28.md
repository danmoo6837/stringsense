## 2. 현황 검토 결과

### 잘 된 점

- 주제 선정이 명확하고 차별화 포인트(줄/프렛 매핑)가 있음
- 기능 명세 문서화 수준이 높음 (목적, 입력, 예외 처리, 테스트 기준까지 포함)
- 프론트 화면 시안 완성 (4개 화면, 자연스러운 흐름)

### 우려 사항

- Demucs, Basic Pitch, pretty_midi 등 외부 라이브러리 비중이 높아 직접 구현 부분이 적게 보일 수 있음
- 발표 시 "직접 설계한 알고리즘"으로 강조할 수 있는 부분이 DP 줄/프렛 매핑 하나임
- 평가 기준이 정량적 수치 없이 데모 가능 여부로만 설정되어 있었음

### 전략 결정

- **DP 매핑 알고리즘을 프로젝트 핵심으로 집중**
- Demucs는 시간상 MVP에서 제외, 단일 기타 입력으로 먼저 완성
- Basic Pitch 대신 librosa CQT 기반 추정으로 먼저 구현 (직접 구현 비중 확보)

## 4. 이번 세션에서 생성한 파일

### 신규 생성

| 파일 | 설명 |
|------|------|
| `requirements.txt` | 프로젝트 의존 패키지 목록 |
| `backend/app/main.py` | FastAPI 앱 진입점, CORS 설정, 프론트엔드 static 서빙 |
| `backend/app/models/schemas.py` | Pydantic 응답 스키마 (`AnalysisResult`) |
| `backend/app/routers/analysis.py` | `POST /analyze`, `GET /files/{job_id}/{filename}`, `GET /raw/{filename}` |
| `backend/app/services/preprocess.py` | librosa 기반 오디오 로드·정규화 (22050Hz, mono, 60초 제한) |
| `backend/app/services/transcribe.py` | CQT + onset detection → note event 목록 반환 |
| `backend/app/services/tab_mapping.py` | **DP 기반 줄/프렛 매핑 (핵심 알고리즘)** |
| `backend/app/services/export_files.py` | pretty_midi로 MIDI 생성, ASCII 탭 렌더링 |
| `backend/app/services/pipeline.py` | 전체 파이프라인 조합 |
| `backend/data/raw/` | 업로드 원본 파일 저장 디렉터리 |
| `backend/data/outputs/` | 결과 파일 저장 디렉터리 (job_id별 폴더) |
| `backend/data/samples/` | 데모용 샘플 파일 디렉터리 |

### 수정

| 파일 | 변경 내용 |
|------|-----------|
| `frontend/app.js` | 실제 API 호출 로직 추가 (fetch POST /analyze, localStorage 활용) |
| `frontend/index.html` | "분석 시작" `<a>` 태그를 `<button id="start-button">`으로 교체 |
| `frontend/result.html` | `id` 추가로 JS 데이터 바인딩 연결 (`tab-preview`, `midi-download`, `note-count`, `original-audio`, `result-filename`) |
| `frontend/tab.html` | `<pre id="tab-full">` 추가로 탭 상세 화면에 실제 결과 표시 |

## 5. 전체 처리 흐름 (구현 완료 기준)

```
POST /analyze (multipart file)
  └─ preprocess.load()         # librosa, 22050Hz mono, 60초 제한
  └─ transcribe.extract_notes() # CQT pitch + onset detection
  └─ tab_mapping.map()          # DP 줄/프렛 최적 경로
  └─ export_files.to_midi()     # pretty_midi → result.mid
  └─ export_files.to_tab()      # ASCII 탭 → result_tab.txt
  └─ AnalysisResult 반환

GET /files/{job_id}/{filename}  # 결과 파일 다운로드
GET /raw/{filename}             # 원본 오디오 재생
```
