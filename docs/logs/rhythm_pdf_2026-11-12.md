# 오디오 기반 템포와 PDF 마디 배치

`rhythm.analyze`는 librosa onset strength와 beat tracking으로 BPM과 박 시각을 추정한다. 검출된 박을 네 개씩 묶어 PDF 마디 경계를 만들고, 각 마디 안에서 음 시작 시각에 비례해 프렛 번호를 배치한다. 한 줄 두 마디 배치는 유지한다.

박자표와 첫 강박은 자동 판별하지 않는다. 4/4와 첫 검출 박을 마디 시작으로 가정한다. 앞부분에 시간이 남으면 첫 마디로 포함하되, 박 길이의 25% 이하인 짧은 여백은 첫 마디에 흡수한다. 마지막은 완전한 마디까지 확장한다. 무음이나 검출 박이 네 개 미만이면 120 BPM을 사용하고 fallback으로 표시한다. 추정 상태는 신뢰도 점수가 아니다. 반박/배박 해석과 강박 위치는 잘못될 수 있다.

API 응답에 `bpm`, `rhythm`을 추가했고 출력 폴더에 `rhythm.json`을 저장한다. MIDI와 TXT의 기존 출력 방식은 유지한다. 음표 길이·쉼표·붙임줄을 그리는 리듬 조판은 아직 지원하지 않는다.

검증: 합성 120 BPM 클릭과 무음 테스트, 기존 PDF 테스트 및 추정 템포/가변 마디 PDF 테스트 총 6개 통과. `00_BN2-166-Ab_solo_mic.wav`에서 약 161.5 BPM이 추정됐다. 정답 템포와의 정확도 평가는 아니다. 기존 평가에서 저장한 estimated 음표를 사용한 미리보기는 `backend/data/outputs/rhythm_preview/result_tab.pdf`에 있다. Docker 엔진이 실행 중이 아니므로 API 전체 실행은 검증하지 못했다.

재검증: Docker 백엔드를 다시 빌드하고 실행한 뒤 동일 샘플을 실제 `/analyze` API에 업로드했다. 작업 `090df377`에서 82개 음과 161.499 BPM이 반환됐다. PDF 다운로드(5,743 bytes, PDF 헤더), 추정 BPM 표기와 마지막 마디를 확인했다. 결과는 `backend/data/outputs/090df377/`에 저장돼 있다. 위의 API 미검증 상태는 이 재검증으로 해소됐다.
