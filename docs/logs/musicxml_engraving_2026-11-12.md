# MuseScore 기반 PDF 조판

직접 벡터를 그리던 ReportLab PDF 생성을 MusicXML → MuseScore PDF 변환으로 교체했다. `backend/app/services/tab_pdf.py`가 MusicXML 생성과 CLI 실행을 담당한다. Docker는 MuseScore 3을 설치하며, 화면 없이 offscreen으로 변환한다. 요청마다 별도 Qt 설정 폴더를 사용하고 변환 제한 시간은 120초다. 실패하면 수동 그림으로 대체하지 않고 오류와 변환 로그를 남긴다.

## 변환 규칙

- 실제 음높이의 피아노식 큰보표(가운데 C 기준 위/아래 배분)와 기타 TAB을 나란한 파트로 기록한다. 피아노 편곡이나 양손 운지 추정은 아니다.
- 검출된 박 시각을 16분음표 격자로 변환한다. 마디 안에 내부 박이 세 개 있을 때 실제 박 간격을 사용하며, 그 외에는 마디 길이를 네 박으로 나눈다.
- 겹치는 서로 다른 음은 화음으로 표시하고 비는 구간은 쉼표로 채운다. 박/음 시작/음 종료/마디 경계에서 나누어진 지속음은 붙임줄로 연결한다.
- 같은 음높이 재타격 시 이전 음의 악보상 지속시간을 끝낸다. 같은 격자에 놓인 동일 음높이는 한 음으로 표현한다.
- 표준 튜닝과 기존 줄·프렛 매핑을 사용한다. MusicXML 줄 번호는 높은 E가 1번이다.
- 두 마디마다 줄바꿈을 기록한다. 기존 PDF URL과 프런트 미리보기는 유지한다. 새 `musicxml_url`로 원본 악보를 받을 수 있다.

## 한계와 검증

4/4·첫 강박 가정과 템포의 반박/배박 오류 가능성은 그대로다. 셋잇단음표·스윙과 독립적인 다성부 리듬은 판별하지 않는다. 음 높이·시각 검출과 줄·프렛 매핑 자체를 개선하는 변경은 아니다. MIDI·성능 평가에는 양자화한 음을 사용하지 않는다.

MusicXML 테스트 6개: 빈 마디 쉼표, 실제 음높이·임시표·TAB 운지, 마디를 넘는 붙임줄과 성부별 마디 박 수, 실제 박 격자, 동일 음 재타격, 두 마디 줄바꿈. 저장된 샘플 음표로 MuseScore 변환에 성공했고 첫 페이지를 렌더링해 오선보·TAB 정렬과 기호를 확인했다.

Docker 재빌드 후 실제 `/analyze` 업로드 검증도 완료했다. `00_BN2-166-Ab_solo_mic.wav` 작업 `2bc1f9d8`: 검출 82음, BPM 161.499, PDF 3페이지(56,479 bytes), MusicXML 132,846 bytes. 두 다운로드 URL이 정상 응답했고 PDF와 MusicXML을 파싱했다. 저장 경로는 `backend/data/outputs/2bc1f9d8/`이다.
