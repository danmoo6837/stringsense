# GuitarSet 실제 백엔드 평가 — 2026-11-04

Docker의 librosa 단일 전사 백엔드에 WAV를 `POST /analyze`로 전달하고, 응답의 `midi_url`에서 내려받은 MIDI를 대응하는 JAMS 정답과 비교했다. 전사 함수를 별도로 호출하거나 정답에 맞춰 결과를 보정하지 않았다.

## 대상과 기준

- 전체 360곡(솔로 180, 반주 180), 성공 360, 실패 0.
- 정답 62,476개, 검출 22,353개. 정답 음높이는 소수 MIDI 값을 유지했다.
- 음 시작 시각 ±50ms, 음높이 ±50센트 허용, mir_eval 0.8.2의 일대일 매칭.
- 종료 시각 포함 평가는 추가로 정답 길이의 20%와 50ms 중 큰 값을 종료 허용 오차로 사용.
- 정답 필터링, 시간 이동 보정, PDF의 120 BPM/4/4 양자화는 적용하지 않았다.
- 음원 길이 14.4~45.7076초로 백엔드 60초 제한에 걸리는 곡은 없다.
- 마이크 음원에 대한 음표 평가이며, 줄/프렛 정확도나 다른 녹음 환경으로의 일반화 성능은 측정하지 않는다.

## 결과

각 그룹의 음표 수를 합산한 micro 지표:

| 대상 | 곡 수 | 정밀도 | 재현율 | F1 |
|---|---:|---:|---:|---:|
| 전체 | 360 | 29.72% | 10.63% | 15.66% |
| 솔로 | 180 | 41.58% | 27.18% | 32.87% |
| 반주 | 180 | 18.18% | 4.52% | 7.24% |

전체에서 정답과 매칭된 음은 6,643개, 오검출은 15,710개, 누락은 55,833개다.

종료 시각까지 포함한 전체 정밀도는 11.05%, 재현율 3.96%, F1 5.83%다. 곡별 F1을 동일 비중으로 평균한 macro F1은 시작+음높이 기준 20.86%, 종료 포함 8.21%다. micro와 macro를 혼용하지 않는다.

현재 구현은 구간별 대표 음높이 하나를 검출하므로 동시 발음이 많은 반주에서 누락될 수 있다. 측정에서도 반주 재현율이 특히 낮다. 다만 이 결과만으로 모든 오류를 단음 분석 탓으로 단정할 수 없으며 시작 시각 검출과 음높이 추정 오류는 별도 분석이 필요하다.

보고서 문장: “GuitarSet 360개 음원을 실제 백엔드 API로 평가한 결과, 시작 시각 ±50ms 및 음높이 ±50센트 기준의 음표 검출 micro F1은 15.66%였다. 솔로 구간은 32.87%, 반주 구간은 7.24%로, 반주에서 높은 음표 누락률을 보였다.”

## 재현 및 산출물

```bash
docker compose up -d --build backend
docker compose --profile evaluation run --rm evaluate
```

실행 결과 폴더: `backend/data/evaluations/20261104T085900204042Z/`

- `summary.json`: 전체/솔로/반주 집계
- `tracks.csv`: 곡별 점수 360행
- 곡별 `.mid`: 실제 API에서 다운로드한 MIDI
- 곡별 `.json`: 정답/검출 음표, API 응답, 입력 파일 해시, 점수
- `config.json`, `environment.md`: 평가 기준 및 실행 환경

요청별 소요 시간 합계는 약 578초이며 첫 실행 초기화 시간을 포함한다. 실행 환경은 Linux/Python 3.11, librosa 0.11.0, numba 0.68.1, numpy 2.4.6, scipy 1.17.1이다. 측정 이미지 ID는 `sha256:3ba8e6d8303e4ff67a24a45d4becddfc394dd4093866a9f7e7da082df9ab5c58`이다.

Docker 백엔드 화면: `http://localhost:8001/ui/index.html`. 측정 종료 후에도 백엔드는 실행 상태로 두었다.
