# 졸업작품 계획서 초안 Ver1

## 1. 작품명

자동 기타 채보 시스템 Stringsense

---

## 2. 작품 개요

본 작품은 사용자가 업로드한 오디오 파일로부터 기타 연주 정보를 분석하여 MIDI와 기타 탭 초안을 자동 생성하는 시스템이다.

기존의 기타 채보 작업은 사용자가 음원을 반복 청취하며 직접 음 높이, 박자, 운지를 추정해야 하므로 시간이 많이 들고 숙련도 의존성이 크다. 본 작품은 이 과정을 자동화하여 사용자가 음원을 업로드한 뒤 결과 화면에서 원본 음원, 기타 분리 음원, MIDI 파일, 기타 탭 초안을 바로 확인할 수 있도록 하는 것을 목표로 한다.

최종적으로는 Web 환경에서 오디오 업로드, 처리 상태 확인, 결과 재생, MIDI 다운로드, 탭 확인이 가능한 형태로 구현한다.

---

## 3. 작품 목표

### 최종 목표

- 오디오 파일 업로드
- 처리 상태 확인
- 기타 분리 음원 및 원본 음원 재생
- MIDI 및 ASCII 기타 탭 생성
- 결과 미리보기 및 다운로드 제공

### 1차 목표

- 단일 기타 또는 기타가 지배적인 음원에서 MIDI와 탭 생성

### 2차 목표

- 혼합 음원에서 기타 성분 분리 후 채보 수행

### 제외 범위

- 벤딩, 슬라이드, 비브라토의 고정밀 표기
- 드롭 튜닝 자동 추정
- 라이브 음원의 고정밀 복원
- 복잡한 재즈 화음 완전 채보

## 4. 주요 기능 및 수행 계획

### [F1] 오디오 업로드 및 전처리

내용:

- `mp3`, `wav` 파일 업로드
- 드래그 앤 드롭 또는 파일 선택 방식 지원
- 샘플레이트 통일
- mono 변환
- 길이 제한 적용
- 내부 분석용 `input.wav` 생성

기술:

- Python 오디오 처리
- librosa
- torchaudio

습득 유무:

- 기본 사용 가능, 세부 전처리 파이프라인은 추가 정리 필요

습득 계획:

- 1주 이내에 입력 포맷 처리와 전처리 흐름 확정

개인 수행 계획:

- 파일 업로드 처리와 입력 검증 구현
- 오디오 전처리 파이프라인 구현

### [F2] 처리 상태 표시

내용:

- 업로드 후 사용자가 현재 처리 진행 상태를 확인
- 분석 중 메시지와 단계별 상태 표시
- 완료 시 결과 화면으로 이동 가능

기술:

- 웹 상태 화면 구성
- 단계별 진행 상태 표시

습득 유무:

- 기본 가능

습득 계획:

- 1주 이내에 처리 중 화면과 상태 전환 흐름 구현

개인 수행 계획:

- 분석 중 화면 구현
- 상태 전환 흐름 구현

### [F3] 기타 음원 분리

내용:

- 혼합 음원에서 기타 성분을 강조한 `guitar_separated.wav` 생성

기술:

- Demucs 기반 소스 분리
- 후처리 gain 조정

습득 유무:

- 모델 사용 경험 없음

습득 계획:

- 2주 이내에 사전학습 모델 실행 및 출력 품질 검증

개인 수행 계획:

- 분리 모델 조사 및 실행 환경 구성
- 분리 결과 평가와 후처리 실험 수행

### [F4] onset 검출

내용:

- 기타 음의 시작 시점을 검출하여 음표 단위 분할 기준 생성

기술:

- onset strength 계산
- peak detection

습득 유무:

- 기본 이론 이해, 실제 파라미터 조정 경험 부족

습득 계획:

- 1주 이내에 샘플 음원 기준 onset 검출 성능 점검

개인 수행 계획:

- onset 알고리즘 구현
- 샘플 기반 파라미터 튜닝

### [F5] pitch 추정 및 note event 생성

내용:

- 각 구간의 음 높이 추정
- `start`, `end`, `pitch` 정보를 갖는 note event 생성

기술:

- STFT/CQT 기반 주파수 분석
- 필요 시 Basic Pitch 같은 사전학습 모델 활용

습득 유무:

- 푸리에 변환 기초 있음, 자동 채보 모델 활용 경험 부족

습득 계획:

- 2주 이내에 신호처리 기반 추정 구현
- 이후 사전학습 모델과 비교 실험

개인 수행 계획:

- STFT/CQT 기반 추정 구현
- 모델 기반 추정 및 비교 실험 수행

### [F6] 박자 정렬 및 줄/프렛 매핑

내용:

- note event를 박자 기준으로 정렬
- MIDI 음을 기타 줄/프렛 위치로 변환
- 연속된 음에 대해 자연스러운 운지 선택

기술:

- BPM 추정
- beat grid 기반 quantization
- 동적 계획법 기반 최적 운지 선택

습득 유무:

- 동적 계획법 기본 지식 있음
- 실제 기타 운지 모델링 경험 없음

습득 계획:

- 2주 이내에 표준 튜닝 기준 후보 생성과 비용 함수 설계 완료

개인 수행 계획:

- quantization 구현
- fretboard 후보 생성 및 동적 계획법 기반 매핑 구현

### [F7] 결과 생성 및 시각화

내용:

- 결과 화면에서 원본 음원 재생
- 결과 화면에서 기타 분리 음원 재생
- MIDI 파일 생성
- ASCII 탭 생성
- 웹에서 결과 재생 및 다운로드 제공
- 탭 상세 화면 제공

기술:

- pretty_midi
- Flask 또는 FastAPI 기반 결과 화면
- HTML/CSS/JavaScript 기반 프론트엔드

습득 유무:

- 웹 기본 구현 가능

습득 계획:

- 2주 이내에 결과 재생, MIDI 다운로드, 탭 보기 화면 구현

개인 수행 계획:

- MIDI 및 탭 파일 생성
- 웹 결과 화면 및 다운로드 기능 구현

## 5. 화면 출력

### 화면 01. 메인 업로드 화면

내용:

- 사용자가 오디오 파일을 업로드
- 드래그 앤 드롭 또는 클릭으로 파일 선택
- 샘플 음원 불러오기
- 분석 시작

기술:

- 웹 파일 업로드
- 입력 검증

습득 유무:

- 있음

습득 계획:

- 초기 1주 내 구현 가능

클릭(버튼 또는 링크):

- ① 파일 선택
- ② 샘플 파일 불러오기
- ③ 분석 시작
- ④ 처리 상태 화면으로 이동

### 화면 02. 처리 상태 화면

내용:

- 분석 중 메시지 출력
- 현재 처리 상태 표시
- 처리 완료 후 결과 화면으로 이동 가능

기술:

- 처리 상태 UI
- 단계 전환 화면 구성

습득 유무:

- 기본 가능

습득 계획:

- 2주 이내에 1차 결과 페이지 구현

클릭(버튼 또는 링크):

- ① 처리 완료 후 결과 화면으로 이동

### 화면 03. 결과 화면

내용:

- 원본 음원 재생
- 기타 분리 음원 재생
- MIDI 다운로드
- 탭 미리보기
- 탭 상세 화면으로 이동
- 새 파일 업로드 화면으로 이동

기술:

- 파일 재생 UI
- 결과 렌더링
- 다운로드 버튼 구성

습득 유무:

- 기본 구현 가능

습득 계획:

- 2주 이내에 결과 재생과 다운로드 화면 구현

클릭(버튼 또는 링크):

- ① 원본 음원 재생
- ② 기타 분리 음원 재생
- ③ MIDI 다운로드
- ④ 탭 상세 보기
- ⑤ 새 파일 업로드

### 화면 04. 탭 상세 보기 화면

내용:

- 생성된 ASCII 탭을 큰 화면에서 확인
- 결과 파일 저장
- 결과 화면으로 이동

기술:

- 텍스트 렌더링
- 결과 파일 저장 버튼 구성

습득 유무:

- 텍스트 기반 구현 가능

습득 계획:

- 1주 이내에 탭 상세 화면 구성 가능

클릭(버튼 또는 링크):

- ① 결과 화면으로 이동
- ② 파일 저장

## 6. 화면들의 상호관계

```text
[화면 01. 메인 업로드]
    ├─ 파일 업로드 / 분석 시작 → [화면 02. 처리 상태]
    └─ 샘플 파일 불러오기

[화면 02. 처리 상태]
    └─ 처리 완료 → [화면 03. 결과 화면]

[화면 03. 결과 화면]
    ├─ 탭 보기 → [화면 04. 탭 상세]
    ├─ MIDI 다운로드
    ├─ 원본 음원 재생
    ├─ 분리 음원 재생
    └─ 새 분석 → [화면 01. 메인 업로드]

[화면 04. 탭 상세]
    ├─ 결과 화면으로 이동 → [화면 03. 결과 화면]
    └─ 파일 저장
```

## 7. 주요 처리 흐름

```text
오디오 업로드
→ 처리 상태 화면 표시
→ 입력 검증 및 전처리
→ 선택적 기타 분리
→ onset 검출
→ pitch 추정
→ note event 생성
→ quantization
→ 줄/프렛 매핑
→ MIDI / 탭 생성
→ 결과 화면 출력
→ 탭 상세 화면 확인
```

## 8. 데이터 및 객체 설계

### AudioJob

- `job_id`: 작업 식별자
- `original_filename`: 원본 파일명
- `stored_path`: 저장 경로
- `status`: 대기, 처리중, 완료, 실패
- `created_at`: 생성 시간

### ResultFile

- `job_id`: 작업 식별자
- `midi_path`: MIDI 파일 경로
- `tab_path`: 탭 파일 경로
- `separated_audio_path`: 선택적 분리 음원 경로

---

## 9. 저장 구조 초안

### 파일 저장

- 원본 파일: `data/raw/`
- 전처리 파일: `data/processed/`
- 결과 파일: `data/outputs/`

### DB 또는 메타데이터 저장 항목

- 작업 ID
- 원본 파일명
- 처리 상태
- 결과 파일 경로
- 처리 일시

초기 버전은 파일 중심 구조로 구현하고, 필요 시 SQLite를 추가한다.

## 14. 결론

본 작품은 기타 연주 음원을 자동 분석하여 MIDI와 기타 탭 초안을 생성하는 시스템을 구현하는 것을 목표로 한다. 신호처리 기반 분석과 모델 기반 보정 방식을 함께 고려함으로써 구현 가능성과 성능을 동시에 확보하고, 최종적으로는 Web 기반 데모 시스템으로 완성하는 것을 목표로 한다.
