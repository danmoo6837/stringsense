## 1. 인사 및 작품 소개

안녕하세요. Stringsense 프로젝트 발표를 시작하겠습니다.

제가 개발한 Stringsense는 기타 연주 오디오 파일을 업로드하면 자동으로 음을 분석해서 MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 자동 채보 서비스입니다.

사용자는 mp3 또는 wav 파일을 업로드하고, 분석 결과 화면에서 원본 오디오를 다시 확인한 뒤, 생성된 MIDI 파일과 ASCII TAB 파일을 다운로드할 수 있습니다.

이 프로젝트의 핵심은 단순히 오디오를 MIDI로 변환하는 것이 아니라, MIDI 음을 실제 기타 줄과 프렛 위치로 변환해서 기타 연주자가 참고할 수 있는 TAB 형태로 제공하는 것입니다.

---

## 2. 문제 정의

기존 기타 채보 작업은 사용자가 음원을 반복해서 들으면서 음 높이, 박자, 운지를 직접 추정해야 합니다.

이 과정은 시간이 많이 걸리고, 기타 연주 경험이나 청음 능력에 따라 결과 품질이 크게 달라집니다.

또 일반적인 오디오-MIDI 변환 도구는 음 높이를 MIDI로 변환하는 데 초점을 두기 때문에, 기타에서 어느 줄과 어느 프렛으로 연주하면 좋은지까지는 알려주지 않는 경우가 많습니다.

그래서 저는 사용자가 음원을 업로드하면 자동으로 분석을 수행하고, MIDI와 기타 TAB 초안을 함께 제공하는 서비스를 목표로 잡았습니다.

---

## 3. 작품 목표와 구현 범위

이번 프로젝트의 최종 목표는 웹 환경에서 다음 흐름이 동작하도록 만드는 것이었습니다.

첫 번째, 사용자가 기타 연주 오디오 파일을 업로드합니다.

두 번째, 백엔드에서 오디오를 분석하여 note event를 추출합니다.

세 번째, 추출된 note event를 MIDI 파일로 저장합니다.

네 번째, MIDI pitch를 기타 줄과 프렛 위치로 매핑합니다.

다섯 번째, 결과 화면에서 MIDI와 TAB을 확인하고 다운로드합니다.

다만 초기 구현 범위에서는 완성된 악보를 만드는 것이 아니라, 사용자가 수정할 수 있는 초안 생성에 집중했습니다. 또한 반주가 섞인 복잡한 음원보다는 단일 기타나 기타 소리가 뚜렷한 음원을 대상으로 했습니다.

---

## 4. 시스템 구조

시스템은 크게 프론트엔드, 백엔드, 분석 파이프라인으로 구성했습니다.

프론트엔드는 HTML, CSS, JavaScript로 구현했습니다. 사용자는 여기서 파일을 선택하고 분석을 시작하며, 결과 화면에서 MIDI와 TAB을 확인합니다.

백엔드는 FastAPI 기반으로 구성했습니다. `/analyze` API에서 업로드 파일을 받고, 분석 파이프라인을 실행한 뒤 결과를 반환합니다.

분석 파이프라인은 전처리, note event 추출, MIDI 생성, 줄/프렛 매핑, TAB 생성 순서로 구성했습니다.

처음에는 librosa 기반 CQT와 onset detection으로 직접 pitch를 추정했지만, 실제 샘플 테스트에서 음 누락과 배음 오검출 문제가 반복되어 최종적으로 Basic Pitch를 우선 사용하는 방식으로 개선했습니다.

---

## 5. 핵심 구현 내용

핵심 구현은 세 가지입니다.

첫 번째는 분석 파이프라인입니다.

업로드된 오디오 파일은 서버에 저장되고, Basic Pitch를 통해 note event 목록으로 변환됩니다. 각 note event에는 시작 시간, 종료 시간, MIDI pitch가 포함됩니다. 이후 pretty_midi를 이용해 `result.mid` 파일을 생성합니다.

두 번째는 기타 줄/프렛 매핑입니다.

기타는 같은 음을 여러 줄과 프렛에서 연주할 수 있습니다. 예를 들어 같은 E 음도 1번 줄 개방현, 2번 줄 5프렛, 3번 줄 9프렛처럼 여러 위치가 가능합니다.

그래서 각 pitch에 대해 가능한 줄/프렛 후보를 만들고, 동적 계획법을 이용해 전체 연주 흐름에서 가장 자연스러운 후보 경로를 선택하도록 했습니다.

초기에는 낮은 프렛을 우선하는 방식이었지만, 실제 TAB을 확인해보니 손이 멀리 이동하는 문제가 있었습니다. 그래서 최종적으로는 전 음과 현재 음 사이의 프렛 이동 거리를 크게 반영하고, 같은 줄에서 멀리 움직이는 것보다 다른 줄의 비슷한 프렛으로 이동하는 쪽을 선호하도록 비용 함수를 수정했습니다.

세 번째는 결과 화면입니다.

결과 화면에서는 원본 오디오를 재생할 수 있고, 생성된 MIDI 파일을 다운로드할 수 있습니다. 또한 TAB 미리보기와 상세 보기 화면을 제공하고, TAB 텍스트도 `result_tab.txt`로 다운로드할 수 있도록 구현했습니다.

## 6. 시연 시나리오

이제 실제 동작 흐름을 시연하겠습니다.

먼저 서버를 실행합니다.

```powershell
conda activate stringsense311
python -m uvicorn app.main:app --reload --app-dir backend
```

브라우저에서 `http://localhost:8000/`에 접속합니다.

첫 화면에서는 오디오 파일을 선택할 수 있습니다. 여기서 준비한 기타 샘플 파일을 선택하고 분석 시작 버튼을 누릅니다.

분석이 완료되면 결과 화면으로 이동합니다.

결과 화면에서는 업로드한 원본 오디오를 다시 재생할 수 있습니다. 그리고 `result.mid` 다운로드 버튼을 눌러 MIDI 파일을 저장할 수 있습니다.

아래에는 자동 생성된 TAB 미리보기가 표시됩니다. 여기서 TAB 크게 보기 버튼을 누르면 전체 ASCII TAB을 더 넓은 화면에서 확인할 수 있습니다.

마지막으로 TAB 다운로드 버튼을 누르면 `result_tab.txt` 파일로 결과를 저장할 수 있습니다.

이 흐름을 통해 사용자는 기타 음원을 업로드하고, MIDI와 TAB 초안을 얻는 전체 과정을 웹에서 수행할 수 있습니다.

## 7. 구현 중 문제와 개선

구현 과정에서 가장 어려웠던 부분은 음 추정 정확도였습니다.

처음에는 librosa의 CQT와 onset detection을 이용해 직접 note event를 만들었습니다. 이 방식은 구조를 직접 설명하기 쉽다는 장점이 있었지만, 실제 기타 샘플에서는 문제가 있었습니다.

한 음이 두 개로 쪼개져 잡히거나, 특정 음이 누락되거나, 높은 배음이 실제로 연주한 음처럼 검출되는 경우가 있었습니다.

이를 해결하기 위해 onset 간격, 최소 note 길이, 같은 pitch 병합 기준 등을 조정했고, 높은 배음이 잡히는 경우 낮은 옥타브 후보를 확인하는 보정도 추가했습니다.

하지만 파라미터 조정만으로는 안정적인 결과를 얻는 데 한계가 있어서, 최종적으로 Basic Pitch 기반 분석을 도입했습니다.

또 다른 문제는 TAB 매핑이었습니다.

처음에는 낮은 프렛을 우선하면 연주하기 쉬울 것이라고 생각했지만, 실제로는 같은 줄에서 멀리 이동하는 경우가 생겼습니다.

그래서 최종 비용 함수에서는 단순히 낮은 프렛을 고르는 것이 아니라, 손 위치가 크게 움직이지 않도록 프렛 이동 거리와 줄 이동 비용의 균형을 조정했습니다.

## 8. 한계 및 향후 개선

현재 구현은 MVP 형태이기 때문에 몇 가지 한계가 있습니다.

첫 번째, 복잡한 반주가 섞인 음원에서는 정확도가 떨어질 수 있습니다. 향후에는 기타 분리 모델을 추가하여 기타 성분을 먼저 분리한 뒤 분석하는 방향으로 개선할 수 있습니다.

두 번째, 현재 TAB은 ASCII 텍스트 형태입니다. 향후에는 VexFlow나 MusicXML을 이용해 더 악보다운 시각적 출력으로 확장할 수 있습니다.

세 번째, 현재는 정량 평가가 부족합니다. 앞으로는 pitch accuracy, onset error, note precision/recall 같은 지표를 이용해 결과 품질을 측정할 수 있습니다.

마지막으로 프론트엔드는 정적 HTML 기반으로 구현했지만, 서비스 형태로 확장한다면 React 또는 Vite 기반으로 상태 관리와 사용자 경험을 개선할 수 있습니다.

---

## 9. 마무리

정리하면, Stringsense는 기타 연주 오디오를 입력받아 MIDI와 기타 TAB 초안을 자동 생성하는 웹 서비스입니다.

이번 프로젝트에서는 FastAPI 기반 백엔드, Basic Pitch 기반 note event 추출, pretty_midi 기반 MIDI 생성, 그리고 DP 기반 기타 줄/프렛 매핑을 구현했습니다.

특히 단순 MIDI 변환에서 끝나는 것이 아니라, 기타 연주자가 실제로 참고할 수 있는 줄과 프렛 기반 TAB 결과를 제공한다는 점이 이 프로젝트의 핵심입니다.

이상으로 발표를 마치겠습니다. 감사합니다.

## 질문 대비 답변 메모

### Q. 왜 Basic Pitch를 사용했나요?

처음에는 librosa 기반 CQT와 onset detection으로 직접 구현했습니다. 하지만 실제 기타 샘플에서 배음 오검출과 음 누락 문제가 반복되어, 최종 결과 안정성을 위해 사전학습 모델인 Basic Pitch를 우선 사용하도록 변경했습니다. 대신 Basic Pitch가 실패하면 기존 librosa 방식으로 fallback 하도록 구성했습니다.

### Q. 직접 구현한 핵심 부분은 무엇인가요?

핵심 직접 구현 부분은 MIDI pitch를 기타 줄/프렛 위치로 변환하는 DP 기반 매핑 알고리즘입니다. 같은 음이 여러 위치에서 연주 가능하기 때문에, 후보를 만들고 프렛 이동 거리와 줄 이동 비용을 계산해 가장 자연스러운 경로를 선택하도록 했습니다.

### Q. 왜 분리음원 기능은 빠졌나요?

초기 계획에는 있었지만, 최종 MVP에서는 단일 기타 또는 기타 소리가 뚜렷한 샘플에서 MIDI와 TAB을 생성하는 것에 집중했습니다. 분리음원은 향후 개선 기능으로 남겼습니다.

### Q. 결과가 완성 악보인가요?

완성 악보라기보다 수정 가능한 초안입니다. 자동 채보 특성상 입력 음원의 품질과 연주 방식에 따라 오차가 있을 수 있기 때문에, 사용자가 빠르게 시작할 수 있는 초안을 제공하는 것을 목표로 했습니다.
