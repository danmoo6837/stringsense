## 3. 작품 설명

Stringsense는 기타 연주 오디오 파일을 업로드하면 자동으로 음을 분석하여 MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 서비스이다. 사용자는 웹 화면에서 mp3 또는 wav 파일을 업로드하고, 결과 화면에서 생성된 MIDI와 ASCII TAB을 확인할 수 있다. 본 프로젝트는 기타 채보 작업의 초기 단계를 자동화하여 사용자가 직접 수정 가능한 형태의 채보 초안을 빠르게 얻을 수 있도록 하는 것을 목표로 한다.

## 4. 주요 기능 및 작업 내용

- 실제 기타 샘플을 이용한 end-to-end 테스트 수행
- MIDI 결과에서 음 누락, 중복 검출, 높은 배음 오검출 문제 확인
- onset detection 감도와 note merge 기준 조정
- CQT 기반 pitch 추정 방식의 한계 분석
- 특정 음역대가 안정적으로 검출되지 않는 문제 확인
- Basic Pitch 기반 분석 방식 도입 검토
- Python 3.11 기반 별도 conda 환경 구성
- `basic-pitch` 의존성 설치 및 import 확인
- Basic Pitch 우선 사용, 실패 시 librosa 방식 fallback 구조 구현

## 6. 진행사항

### 12주차까지의 작업 내용

12주차에는 프론트엔드와 백엔드를 end-to-end로 연결하였다. 사용자가 파일을 업로드하면 `/analyze` API로 전송되고, 백엔드 분석 결과가 `localStorage`에 저장된 뒤 결과 화면에서 MIDI 다운로드와 TAB 미리보기를 확인할 수 있도록 구성하였다. 또한 실제 제공하지 않는 분리음원 UI를 제거하고, 결과가 없는 상태에서 화면에 접근했을 때 안내 메시지가 표시되도록 개선하였다.

### 13주차 작업 내용

이번 주에는 실제 기타 샘플을 이용하여 분석 결과의 품질을 점검하고, MIDI와 TAB 생성 결과를 개선하는 작업을 진행하였다. 기존에는 구현된 파이프라인이 정상적으로 연결되는지 확인하는 수준이었다면, 이번 주에는 실제 wav/mp3 파일을 업로드하여 생성된 MIDI 파일을 직접 들어보고 TAB 결과를 확인하는 방식으로 테스트를 수행하였다.

테스트 과정에서 몇 가지 문제가 확인되었다. 첫째, 한 번만 연주한 음이 MIDI에서는 두 개 이상의 음으로 나뉘어 출력되는 경우가 있었다. 이는 onset detection이 피킹 직후의 잔향이나 배음을 새로운 음의 시작으로 잘못 판단했기 때문으로 보였다. 이를 완화하기 위해 최소 note 길이, onset 간 최소 간격, 같은 pitch가 짧은 간격으로 반복될 경우 병합하는 기준을 조정하였다.

둘째, 실제로 연주하지 않은 높은 음이 MIDI에 포함되는 경우가 있었다. 기타 음원은 기본음보다 배음 성분이 강하게 나타나는 경우가 있어, CQT 기반 pitch 추정에서 높은 배음이 실제 pitch처럼 선택되는 문제가 발생하였다. 이를 줄이기 위해 CQT fallback 과정에서 한 옥타브 또는 두 옥타브 아래의 에너지도 함께 확인하여, 낮은 기본음 후보가 충분히 존재하면 해당 음을 우선 선택하도록 보정하였다.

셋째, 특정 음이 누락되는 문제가 있었다. 특히 피킹이 약하거나 앞뒤 음과 이어져 들리는 경우에는 onset으로 잡히지 않아 note event가 생성되지 않았다. 이를 해결하기 위해 onset 후보만 사용하는 방식에서 벗어나, pitch가 일정 이상 변화하는 지점도 note 시작 후보로 추가하는 방식을 실험하였다. 다만 이 방식은 민감도를 높이면 없는 음이 추가로 검출되는 문제가 있어, 파라미터 조정만으로는 안정적인 결과를 얻는 데 한계가 있음을 확인하였다.

이러한 테스트 결과를 바탕으로 기존 `librosa` 기반 CQT pitch 추정 방식만으로는 발표용 샘플에서도 결과가 불안정할 수 있다고 판단하였다. 따라서 사전학습 모델 기반의 Basic Pitch를 도입하기로 하였다. Basic Pitch는 오디오에서 note event를 직접 추정하는 모델이기 때문에, 직접 구현한 onset/pitch 조합 방식보다 기타 샘플에서 더 안정적인 결과를 기대할 수 있다.

Basic Pitch를 사용하기 위해 개발 환경도 정리하였다. 기존 conda 환경은 Python 3.13 기반이었는데, Basic Pitch와 TensorFlow 계열 의존성이 Python 3.13과 맞지 않아 설치가 실패하였다. 이에 Python 3.11 기반의 `stringsense311` conda 환경을 새로 생성하고, 프로젝트 의존성과 `basic-pitch`를 설치하였다. 설치 과정에서 `resampy`가 `pkg_resources`를 요구하는 문제가 있어 `setuptools<81` 조건을 추가하여 호환성을 맞추었다.

코드 구조에서는 `transcribe.py`를 Basic Pitch 우선 방식으로 변경하였다. 원본 오디오 파일 경로가 있으면 Basic Pitch를 먼저 사용하여 note event를 추출하고, Basic Pitch import 또는 예측 과정에서 문제가 발생하면 기존 `librosa` 기반 방식으로 fallback 하도록 구성하였다. 이를 통해 새 환경에서는 Basic Pitch 기반 분석을 사용할 수 있고, Basic Pitch가 없는 환경에서도 기존 방식으로 최소한의 동작이 가능하도록 하였다.

## 7. 문제점 및 해결 내용

| 문제점 | 해결 내용 |
|---|---|
| 한 음이 여러 음으로 쪼개져 MIDI에 출력됨 | 최소 note 길이, onset 간격, 같은 pitch 병합 기준 조정 |
| 연주하지 않은 높은 음이 검출됨 | CQT fallback에서 낮은 옥타브 기본음 후보를 우선하도록 보정 |
| 특정 음이 누락됨 | pitch 변화 지점도 note 시작 후보로 추가하는 방식 실험 |
| librosa 기반 방식의 파라미터 조정 한계 확인 | Basic Pitch 기반 분석 방식으로 전환 |
| Basic Pitch가 기존 Python 3.13 환경에서 설치되지 않음 | Python 3.11 conda 환경 `stringsense311` 생성 |
| Basic Pitch import 시 `pkg_resources` 오류 발생 | `setuptools<81` 조건을 추가하여 호환성 확보 |

## 10. 종합 의견

13주차에는 실제 샘플을 사용하면서 기존 분석 방식의 장단점을 구체적으로 확인할 수 있었다. 단순한 CQT 기반 pitch 추정은 직접 구현 비중이 높다는 장점이 있었지만, 실제 기타 음원에서는 배음, 잔향, 약한 피킹 등으로 인해 음 누락과 오검출 문제가 반복적으로 발생하였다. 이를 해결하기 위해 여러 파라미터를 조정하였으나, 안정적인 결과를 얻기 위해서는 사전학습 모델 기반 접근이 필요하다고 판단하였다. 이에 Basic Pitch를 도입하고 Python 3.11 환경을 새로 구성하여, 다음 주에는 Basic Pitch 결과를 바탕으로 TAB 매핑과 최종 시연 흐름을 정리할 예정이다.
