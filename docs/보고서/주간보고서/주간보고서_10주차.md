## 2. 작품명

## 3. 작품 설명

Stringsense는 사용자가 업로드한 기타 연주 오디오 파일을 분석하여 MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 자동 채보 서비스이다. 사용자는 웹 화면에서 mp3 또는 wav 파일을 업로드하고, 백엔드 분석 과정을 거친 뒤 결과 화면에서 원본 오디오, MIDI 파일, ASCII TAB 결과를 확인할 수 있다. 본 프로젝트는 단순히 오디오를 MIDI로 변환하는 것에 그치지 않고, MIDI 음을 실제 기타 줄과 프렛 위치로 변환하여 사용자가 연주 가능한 형태의 초안을 제공하는 것을 목표로 한다.

## 4. 주요 기능 및 작업 내용

- FastAPI 기반 분석 API와 실제 분석 파이프라인 연결
- 업로드된 오디오 파일을 서버 내부 저장 경로에 저장하는 구조 정리
- librosa 기반 오디오 전처리 모듈 구현 및 파이프라인에 연결
- onset detection과 pitch 추정을 이용한 note event 생성 흐름 구성
- pretty_midi를 이용한 MIDI 파일 생성 기능 구현
- ASCII TAB 파일 생성을 위한 기본 출력 구조 연결
- 분석 결과 파일을 job_id 기준 폴더에 저장하도록 구성
- 프론트엔드에서 `/analyze` API 호출 후 결과 화면으로 이동하는 흐름 점검

## 6. 진행사항

### 9주차까지의 작업 내용

이전 주차까지는 프로젝트의 전체 구조를 정리하고, 프론트엔드 화면과 백엔드 기본 구조를 구현하였다. 프론트엔드에는 분석 시작 화면, 처리 상태 화면, 결과 화면, TAB 상세 화면을 구성하였고, 백엔드에는 FastAPI 앱 진입점과 기본 라우터 구조를 마련하였다. 또한 업로드 API와 결과 파일 제공 API의 기본 형태를 구성하여 프론트엔드와 백엔드가 통신할 수 있는 기반을 마련하였다.

### 10주차 작업 내용

이번 주에는 기존에 분리되어 있던 백엔드 구조를 실제 분석 흐름과 연결하는 작업을 진행하였다. `POST /analyze` API에서 업로드된 오디오 파일을 수신한 뒤, 해당 파일을 서버 내부의 `backend/data/raw/` 경로에 저장하도록 구현하였다. 이후 분석 결과를 구분하기 위해 각 요청마다 `job_id`를 생성하고, 결과 파일은 `backend/data/outputs/{job_id}/` 경로에 저장하도록 구성하였다.

오디오 전처리 단계에서는 `librosa`를 사용하여 업로드된 mp3 또는 wav 파일을 로드하고, 분석에 적합하도록 22050Hz 샘플레이트와 mono 채널로 변환하였다. 또한 지나치게 긴 파일로 인해 처리 시간이 길어지는 문제를 줄이기 위해 최대 60초까지만 분석하도록 제한하였다. 이 전처리 과정을 통해 다양한 입력 파일을 일정한 형식으로 맞춘 뒤 이후 분석 단계에서 사용할 수 있도록 하였다.

채보 분석 단계에서는 onset detection과 CQT 기반 pitch 추정을 이용하여 note event 목록을 생성하는 흐름을 구현하였다. 각 note event는 시작 시간, 종료 시간, MIDI pitch 정보를 포함하도록 구성하였으며, 기타 연주 가능 음역을 벗어나는 pitch는 제외하도록 처리하였다. 이를 통해 오디오 파일에서 추정된 음 정보를 MIDI와 TAB 생성 단계에서 공통으로 사용할 수 있도록 하였다.

결과 생성 단계에서는 `pretty_midi`를 이용하여 note event 목록을 `result.mid` 파일로 변환하였다. 생성된 MIDI 파일은 일반 MIDI 플레이어나 DAW에서 재생 가능한 형태로 저장되며, 분석 결과 폴더에 함께 보관되도록 하였다. 또한 TAB 결과 생성을 위한 ASCII TAB 출력 구조도 연결하여, 분석 결과가 단순 데이터가 아니라 사용자가 확인할 수 있는 파일 형태로 생성되도록 하였다.

프론트엔드와의 연결도 함께 점검하였다. 사용자가 분석 시작 버튼을 누르면 `frontend/app.js`에서 `fetch`를 통해 `/analyze` API로 파일을 전송하고, 백엔드가 반환한 분석 결과를 `localStorage`에 저장한 뒤 결과 화면으로 이동하도록 하였다. 이를 통해 프론트엔드 화면에서 실제 백엔드 분석 결과를 확인할 수 있는 end-to-end 흐름의 기초를 마련하였다.

## 7. 문제점 및 해결 내용

| 문제점 | 해결 내용 |
|---|---|
| 업로드 파일과 결과 파일을 구분하기 어려움 | 요청마다 `job_id`를 생성하여 raw 파일과 output 파일을 구분하도록 구성 |
| 입력 오디오 형식이 일정하지 않음 | librosa 전처리 단계에서 sample rate, mono 변환, 길이 제한을 적용 |
| 분석 결과를 파일로 확인하기 어려움 | MIDI 파일과 ASCII TAB 텍스트 파일을 output 경로에 저장하도록 구현 |
| 프론트엔드와 백엔드 결과 전달 방식이 불명확함 | Pydantic 응답 스키마를 정의하고 `midi_url`, `tab`, `note_count` 등을 반환하도록 구성 |
