## 2. 작품명

- Stringsense - AI 기반 기타 자동 채보 웹서비스

## 3. 작품 설명

Stringsense는 기타 연주 오디오 파일을 업로드하면 자동으로 음을 분석하고, MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 서비스이다. 사용자는 별도의 프로그램을 설치하지 않고 웹 화면에서 음원을 업로드한 뒤, 분석 결과로 생성된 MIDI 파일과 ASCII TAB을 확인하고 다운로드할 수 있다. 본 프로젝트는 기타 채보 작업의 초기 과정을 자동화하여 사용자가 수정 가능한 초안을 빠르게 얻을 수 있도록 하는 것을 목표로 한다.

## 4. 주요 기능 및 작업 내용

- 프론트엔드 업로드 화면과 `/analyze` API 연결
- `fetch`와 `FormData`를 이용한 오디오 파일 업로드 처리
- 백엔드 분석 결과를 `localStorage`에 저장하는 흐름 구현
- 결과 화면에서 원본 오디오 재생 기능 연결
- MIDI 파일 다운로드 링크 연결
- TAB 미리보기 영역에 실제 분석 결과 표시
- TAB 상세 화면에서 전체 ASCII TAB 표시
- 결과가 없는 상태에서 화면에 접근했을 때 안내 메시지 표시
- 백엔드 응답 스키마에 결과 파일 경로와 TAB 데이터를 포함하도록 정리

## 6. 진행사항

### 11주차까지의 작업 내용

11주차에는 MIDI pitch를 기타 줄과 프렛 위치로 변환하는 DP 기반 매핑 알고리즘을 구현하였다. 각 pitch에 대해 가능한 `(string, fret)` 후보를 생성하고, 프렛 이동 거리와 줄 이동 거리 등을 고려하여 전체 note sequence에서 가장 자연스러운 경로를 선택하도록 구성하였다. 이를 통해 MIDI 결과를 실제 기타 TAB 형태로 변환할 수 있는 기반을 마련하였다.

### 12주차 작업 내용

이번 주에는 백엔드에서 생성된 분석 결과를 프론트엔드 화면에서 실제로 확인할 수 있도록 end-to-end 연결 작업을 진행하였다. 기존 프론트엔드는 화면 시안 중심으로 구성되어 있었기 때문에, 분석 시작 버튼을 눌렀을 때 실제 서버로 파일이 전송되고 결과 화면에 데이터가 표시되도록 JavaScript 로직을 보완하였다.

먼저 `frontend/app.js`에서 파일 입력 요소를 읽어 사용자가 선택한 mp3 또는 wav 파일을 `FormData`에 담도록 구현하였다. 사용자가 분석 시작 버튼을 클릭하면 `fetch`를 이용해 `POST /analyze` API로 파일을 전송하고, 백엔드에서 분석이 완료되면 응답 JSON을 받아 `localStorage`에 저장하도록 하였다. 이후 자동으로 `result.html`로 이동하게 하여 사용자가 별도 조작 없이 결과 화면으로 이어지도록 구성하였다.

결과 화면에서는 `localStorage`에 저장된 분석 결과를 읽어 화면 요소에 바인딩하였다. `result.mid` 다운로드 링크는 백엔드가 반환한 `midi_url`을 이용하여 연결하였고, 원본 오디오 재생 영역에는 `original_audio_url`을 연결하였다. 또한 검출된 음표 수와 job_id를 함께 표시하여 사용자가 어떤 분석 결과를 보고 있는지 확인할 수 있도록 하였다.

TAB 결과 표시도 함께 연결하였다. 백엔드에서 반환된 ASCII TAB 문자열을 결과 화면의 미리보기 영역에 표시하고, `tab.html`에서는 같은 데이터를 더 큰 영역에서 확인할 수 있도록 구성하였다. 이를 통해 사용자는 분석 결과 화면에서는 요약된 TAB을 확인하고, 상세 화면에서는 전체 TAB을 보다 편하게 볼 수 있다.

또한 결과 파일 다운로드 흐름을 정리하였다. MIDI 파일은 백엔드의 파일 다운로드 API를 통해 제공하고, TAB 텍스트는 화면에 표시된 데이터를 기반으로 `result_tab.txt` 파일로 다운로드할 수 있도록 구성하였다. 이를 통해 실제 파일 경로 문제나 이전 분석 결과 캐시 문제와 관계없이 사용자가 TAB 파일을 저장할 수 있도록 개선하였다.

마지막으로 예외 상황도 보완하였다. 사용자가 분석을 수행하지 않고 결과 화면이나 TAB 상세 화면에 직접 접근한 경우에는 빈 화면이 표시되지 않도록 “불러올 결과가 없습니다” 안내 메시지를 표시하고, 새 파일 분석 화면으로 이동할 수 있는 버튼을 제공하였다. 이를 통해 전체 사용자 흐름이 보다 안정적으로 동작하도록 하였다.

## 7. 문제점 및 해결 내용

| 문제점 | 해결 내용 |
|---|---|
| 프론트엔드 화면이 실제 API와 연결되지 않음 | `fetch`와 `FormData`를 이용해 `/analyze` API 호출 구현 |
| 결과 화면으로 데이터를 전달할 방법이 필요함 | 분석 응답을 `localStorage`에 저장한 뒤 결과 화면에서 다시 읽도록 구성 |
| MIDI 다운로드 링크가 동적으로 설정되어야 함 | 백엔드 응답의 `midi_url`을 이용해 다운로드 링크 바인딩 |
| TAB 파일 다운로드가 안정적으로 동작하지 않음 | 화면에 표시된 TAB 문자열을 Blob으로 만들어 `result_tab.txt`로 다운로드 |
| 분석 전 결과 화면 접근 시 빈 화면이 표시됨 | 결과 없음 상태 안내 UI와 새 분석 버튼 추가 |
| 실제 생성하지 않는 분리음원 UI가 혼란을 줌 | 결과 화면에서 분리음원 재생/다운로드 영역을 제거하고 실제 제공 기능만 표시 |
