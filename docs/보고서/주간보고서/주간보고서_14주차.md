## 3. 작품 설명

Stringsense는 기타 연주 오디오 파일을 업로드하면 자동으로 음을 분석하고, MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 서비스이다. 사용자는 웹 화면에서 음원을 업로드한 뒤 원본 오디오를 확인하고, 생성된 MIDI 파일과 ASCII TAB을 다운로드할 수 있다. 본 프로젝트는 기타 채보 작업의 초기 단계를 자동화하여 사용자가 직접 수정 가능한 연주 초안을 빠르게 얻을 수 있도록 하는 것을 목표로 한다.

## 4. 주요 기능 및 작업 내용

- Basic Pitch 기반 note event 추출 흐름 점검
- 기타 줄/프렛 매핑 비용 함수 고도화
- 낮은 프렛 우선 방식에서 손 위치 유지 우선 방식으로 매핑 기준 수정
- 같은 줄에서 멀리 이동하는 경우보다 다른 줄의 비슷한 프렛을 선택하도록 비용 조정
- 결과 화면에서 실제 제공 기능 중심으로 UI 정리
- 분리음원 안내 및 더미 기능 제거
- MIDI 다운로드와 TAB 텍스트 다운로드 기능 최종 점검
- README 실행 방법 및 Python 3.11 환경 사용 안내 정리
- 발표용 시연 흐름과 샘플 준비

## 6. 진행사항

### 13주차까지의 작업 내용

13주차에는 실제 기타 샘플을 이용하여 분석 결과를 테스트하고, 기존 `librosa` 기반 pitch 추정 방식의 한계를 확인하였다. 한 음이 여러 개로 쪼개지거나, 특정 음이 누락되거나, 높은 배음이 실제 음처럼 검출되는 문제가 발생하였다. 이를 보완하기 위해 onset 및 pitch 관련 파라미터를 조정하였으나, 안정적인 결과를 얻기 위해 Basic Pitch 기반 분석 방식으로 전환하였다. 또한 Python 3.11 기반 `stringsense311` conda 환경을 구성하고 Basic Pitch 의존성을 설치하였다.

### 14주차 작업 내용

이번 주에는 최종 발표와 시연을 위해 결과 품질과 사용자 화면을 정리하는 작업을 진행하였다. 먼저 Basic Pitch 기반으로 생성된 note event가 기존 파이프라인의 MIDI 생성 및 TAB 매핑 단계와 정상적으로 연결되는지 확인하였다. Basic Pitch가 동작하는 환경에서는 이를 우선 사용하고, 문제가 발생할 경우 기존 `librosa` 방식으로 fallback 하도록 구성하여 분석 파이프라인의 안정성을 확보하였다.

이후 TAB 매핑 결과를 실제 기타 연주 관점에서 다시 점검하였다. 기존 매핑 방식은 낮은 프렛을 우선 선택하는 경향이 있었기 때문에, 경우에 따라 손이 같은 줄에서 멀리 이동하는 형태의 TAB이 생성될 수 있었다. 그러나 실제 기타 연주에서는 단순히 낮은 프렛만 선택하는 것보다, 손 위치가 크게 움직이지 않도록 같은 포지션 안에서 줄을 바꾸는 것이 더 자연스러운 경우가 많다.

이를 반영하여 `tab_mapping.py`의 DP 비용 함수를 수정하였다. 기존에는 높은 프렛 사용 비용을 크게 두는 방식이었다면, 이번 주에는 전 음과 현재 음 사이의 프렛 이동 거리를 더 중요하게 보도록 변경하였다. 같은 줄에서 멀리 떨어진 프렛으로 이동하는 경우에는 큰 페널티를 부여하고, 다른 줄이라도 이전 프렛과 같거나 비슷한 프렛을 선택하는 경우에는 비용을 낮추도록 조정하였다. 이를 통해 TAB 결과가 같은 포지션 안에서 줄을 이동하는 형태로 더 자연스럽게 생성되도록 개선하였다.

프론트엔드 결과 화면도 최종 시연에 맞게 정리하였다. 현재 MVP에서는 기타 분리음원을 실제로 생성하지 않기 때문에, 결과 화면에서 분리음원 재생이나 다운로드처럼 동작하지 않는 UI를 제거하였다. 대신 원본 오디오 재생, MIDI 다운로드, TAB 미리보기, TAB 상세 보기, TAB 텍스트 다운로드처럼 실제로 동작하는 기능만 남겨 사용자에게 혼란을 주지 않도록 하였다.

또한 TAB 다운로드 기능을 안정화하였다. 백엔드 파일 경로에 의존하는 방식만 사용할 경우 이전 분석 결과나 캐시 상태에 따라 다운로드가 실패할 수 있으므로, 화면에 표시된 TAB 문자열을 기반으로 브라우저에서 직접 `result_tab.txt` 파일을 생성해 다운로드하도록 수정하였다. 이를 통해 사용자는 결과 화면과 TAB 상세 화면에서 동일한 TAB 내용을 안정적으로 저장할 수 있다.

마지막으로 실행 환경과 발표 준비를 정리하였다. Basic Pitch는 Python 3.13 환경에서 설치가 원활하지 않았기 때문에, Python 3.11 기반 `stringsense311` 환경을 사용하도록 README에 실행 방법을 정리하였다. 발표 시에는 해당 환경을 활성화한 뒤 FastAPI 서버를 실행하고, 준비한 기타 샘플을 업로드하여 MIDI와 TAB 결과를 보여주는 흐름으로 시연할 수 있도록 점검하였다.

## 7. 문제점 및 해결 내용

| 문제점 | 해결 내용 |
|---|---|
| 낮은 프렛만 우선하면 손이 멀리 이동하는 TAB이 생성됨 | 프렛 이동 거리 비용을 높이고, 같은 포지션 안에서 줄 이동을 선호하도록 비용 함수 수정 |
| 같은 줄에서 멀리 떨어진 프렛으로 이동하는 경우가 발생 | 같은 줄의 큰 프렛 이동에 추가 페널티 적용 |
| 다른 줄의 비슷한 프렛이 더 자연스러운 경우가 반영되지 않음 | 다른 줄이라도 이전 프렛과 비슷하면 비용을 낮추도록 조정 |
| 실제 생성하지 않는 분리음원 UI가 결과 화면에 남아 있음 | 분리음원 안내 및 더미 재생/다운로드 영역 제거 |
| TAB 텍스트 다운로드가 환경에 따라 실패할 수 있음 | 화면의 TAB 문자열을 Blob으로 변환하여 `result_tab.txt` 다운로드 구현 |
| Basic Pitch 실행 환경이 기존 Python 버전과 맞지 않음 | Python 3.11 conda 환경을 새로 구성하고 README에 실행 방법 정리 |

## 8. 최종 시연 흐름

1. `conda activate stringsense311`로 Python 3.11 환경을 활성화한다.
2. `python -m uvicorn app.main:app --reload --app-dir backend` 명령으로 FastAPI 서버를 실행한다.
3. 브라우저에서 `http://localhost:8000/`에 접속한다.
4. 준비한 기타 샘플 wav 또는 mp3 파일을 업로드한다.
5. 분석 완료 후 결과 화면에서 원본 오디오를 확인한다.
6. 생성된 `result.mid` 파일을 다운로드하여 재생 가능한 MIDI 결과를 확인한다.
7. TAB 미리보기 및 TAB 상세 화면에서 ASCII TAB 결과를 확인한다.
8. `result_tab.txt` 파일을 다운로드하여 최종 결과 파일을 저장한다.

## 10. 향후 개선 방향

- 기타 분리음원 기능을 추가하여 반주가 포함된 음원에서도 안정적으로 분석할 수 있도록 개선
- MusicXML 출력 기능을 추가하여 악보 편집 프로그램과 연동
- pitch accuracy, onset error, note precision/recall 등 정량 평가 지표 도입
- TAB 결과를 ASCII뿐 아니라 시각적인 악보 형태로 렌더링
- React 또는 Vite 기반 프론트엔드로 확장하여 상태 관리와 사용자 경험 개선
- 다양한 기타 연주 기법과 빠른 리프에 대한 분석 안정성 개선

## 11. 종합 의견

14주차에는 최종 발표를 앞두고 기능 확장보다는 시연 안정성과 결과의 자연스러움을 개선하는 데 집중하였다. Basic Pitch 기반 분석 흐름을 정리하고, 기타 TAB 매핑에서는 단순히 낮은 프렛을 선택하는 방식에서 벗어나 손 위치가 크게 움직이지 않는 방향으로 비용 함수를 조정하였다. 또한 실제로 제공하지 않는 기능은 화면에서 제거하고, MIDI와 TAB 다운로드처럼 시연에서 보여줄 핵심 기능을 안정적으로 동작하도록 정리하였다. 이를 통해 Stringsense는 오디오 업로드, MIDI 생성, 기타 TAB 초안 확인이라는 MVP 목표를 수행할 수 있는 형태로 마무리되었다.
