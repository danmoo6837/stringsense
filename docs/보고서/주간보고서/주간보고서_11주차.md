## 2. 작품명

- Stringsense - AI 기반 기타 자동 채보 웹서비스

## 3. 작품 설명

Stringsense는 사용자가 업로드한 기타 연주 오디오 파일을 분석하여 MIDI 파일과 기타 TAB 초안을 생성하는 웹 기반 자동 채보 서비스이다. 본 프로젝트는 오디오에서 음의 높이와 시작 시점을 추정한 뒤, 이를 MIDI 파일로 변환하고 다시 기타에서 실제로 연주 가능한 줄과 프렛 위치로 매핑하는 것을 목표로 한다. 이를 통해 사용자는 단순한 MIDI 결과뿐 아니라 기타 연주에 참고할 수 있는 TAB 형태의 결과를 확인할 수 있다.

## 4. 주요 기능 및 작업 내용

- 표준 기타 튜닝 기준 open string MIDI 값 정의
- 각 MIDI pitch에 대해 가능한 줄/프렛 후보 생성
- 기타 연주 가능 프렛 범위 설정
- DP 기반 줄/프렛 최적 경로 선택 알고리즘 구현
- 프렛 이동 거리와 줄 이동 거리를 고려한 비용 함수 작성
- 높은 프렛 사용 및 과도한 포지션 이동에 대한 페널티 적용
- note event 목록을 TAB event 목록으로 변환하는 서비스 로직 구성
- ASCII TAB 출력 결과와 매핑 결과의 일관성 점검

## 6. 진행사항

### 10주차까지의 작업 내용

10주차에는 업로드된 오디오 파일이 전처리, note event 생성, MIDI 파일 생성 단계까지 이어지도록 분석 파이프라인을 연결하였다. `POST /analyze` API를 통해 파일을 업로드하고, `librosa` 기반 전처리 및 pitch 추정을 수행한 뒤, `pretty_midi`를 이용하여 `result.mid` 파일을 생성하는 흐름을 구현하였다. 이를 통해 백엔드에서 실제 분석 결과 파일을 생성할 수 있는 기반을 마련하였다.

### 11주차 작업 내용

이번 주에는 MIDI pitch 정보를 실제 기타 TAB으로 변환하기 위한 줄/프렛 매핑 알고리즘을 구현하였다. 기타는 같은 pitch를 여러 줄과 프렛 위치에서 연주할 수 있기 때문에, 단순히 pitch를 프렛 번호로 변환하는 방식만으로는 자연스러운 TAB을 생성하기 어렵다. 따라서 각 note event마다 가능한 `(string, fret)` 후보를 생성하고, 전체 note sequence에서 가장 자연스러운 후보 조합을 선택하는 방식으로 접근하였다.

먼저 표준 튜닝을 기준으로 각 줄의 open string MIDI 값을 정의하였다. 6번 줄 E2부터 1번 줄 e4까지의 MIDI 값을 배열로 관리하고, 입력 pitch에서 각 open string 값을 빼는 방식으로 해당 줄에서 필요한 프렛 번호를 계산하였다. 계산된 프렛이 0 이상이고 최대 프렛 범위 안에 있을 경우에만 유효한 후보로 추가하였다. 이를 통해 하나의 pitch에 대해 여러 줄에서 가능한 연주 위치를 후보 목록으로 만들 수 있었다.

이후 후보 목록 중 최적의 경로를 선택하기 위해 동적 계획법(DP)을 적용하였다. 각 note마다 가능한 후보가 여러 개 존재하므로, 현재 note에서 어떤 줄/프렛을 선택하느냐에 따라 다음 note의 이동 비용이 달라진다. 따라서 단순히 각 note별로 낮은 프렛을 고르는 것이 아니라, 전체 연주 흐름에서 이동 비용이 가장 낮은 경로를 선택하도록 DP 테이블을 구성하였다.

비용 함수에는 프렛 이동 거리, 줄 이동 거리, 높은 프렛 사용 비용, 과도한 포지션 이동 페널티를 반영하였다. 초기 구현에서는 낮은 프렛을 선호하도록 비용을 설정하였고, 같은 줄에서 프렛 이동이 지나치게 커지는 경우 추가 페널티를 부여하였다. 이를 통해 생성되는 TAB이 실제 기타 연주 관점에서 지나치게 비현실적인 위치로 이동하지 않도록 하였다.

또한 `tab_mapping.py` 서비스를 통해 note event 목록을 TAB event 목록으로 변환하도록 구성하였다. 변환된 TAB event에는 기존 note event의 시작 시간, 종료 시간, pitch 정보에 더해 string과 fret 정보가 포함된다. 이후 `export_files.py`에서 이 정보를 바탕으로 ASCII TAB 문자열을 생성하도록 연결하였다.

## 7. 문제점 및 해결 내용

| 문제점 | 해결 내용 |
|---|---|
| 같은 pitch가 여러 줄에서 연주 가능하여 단순 변환이 어려움 | 각 pitch마다 가능한 `(string, fret)` 후보를 모두 생성 |
| 낮은 프렛만 선택하면 전체 연주 흐름이 부자연스러울 수 있음 | DP 기반으로 전체 note sequence의 이동 비용을 계산 |
| 프렛 이동이 과도하게 커지는 경우가 발생 | 프렛 이동 거리와 큰 포지션 이동에 페널티 적용 |
| 기타 연주 가능 범위를 벗어나는 pitch 처리 필요 | 유효한 프렛 범위 안에 있는 후보만 사용하도록 필터링 |
| TAB 결과가 MIDI와 별도 구조로 분리될 필요가 있음 | note event를 tab event로 변환하는 별도 매핑 서비스 구성 |

## 10. 종합 의견

11주차에는 Stringsense의 핵심 기능 중 하나인 MIDI pitch의 기타 줄/프렛 매핑 알고리즘을 구현하였다. 단순 MIDI 변환 결과만 제공하는 것이 아니라, 실제 기타에서 연주 가능한 위치 정보를 함께 제공하기 위한 기반을 마련했다는 점에서 의미가 있다. 특히 같은 음을 여러 위치에서 연주할 수 있는 기타의 특성을 고려하여 DP 기반으로 전체 경로를 선택하도록 구성함으로써, 이후 TAB 결과의 자연스러움을 개선할 수 있는 구조를 만들었다. 다음 주에는 이 매핑 결과를 프론트엔드 결과 화면과 연결하여 사용자가 웹에서 직접 확인할 수 있도록 구현할 예정이다.
