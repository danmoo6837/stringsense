# 발표 대본

## 1번 슬라이드

안녕하세요. 발표 시작하겠습니다. 
발표 주제는 자동 기타 패보 웹서비스 입니다. 오디오 파일에서 기타 연주 정보를 추출해서 MIDI와 기타 탭 초안을 자동으로 생성하는 시스템입니다.  
사용자는 음원을 업로드하기만 하면 분석 결과를 웹에서 확인할 수 있도록 하는 것이 목표입니다.

## 2번 슬라이드

먼저 작품 개요입니다.  
기존 기타 채보 작업은 음원을 여러 번 반복해서 들으면서 음 높이, 박자, 운지를 직접 추정해야 하기 때문에 시간이 많이 걸립니다.  
또 숙련도가 낮으면 정확한 채보가 어렵고, 일반적인 MIDI 변환 도구는 기타 전용 줄과 프렛 정보까지 제공하지 못합니다.  
그래서 음원 업로드만으로 분석을 자동으로 시작하고, onset과 pitch를 추출해서 MIDI와 기타 탭 초안을 함께 제공하는 방향으로 설계했습니다.

## 3번 슬라이드

다음은 작품 목표입니다.  
최종적으로는 사용자가 mp3나 wav 파일을 업로드하고, 처리 상태를 확인한 뒤, 기타 분리 음원을 재생하고, MIDI 파일을 다운로드하고, ASCII 기타 탭을 확인할 수 있는 시스템을 만드는 것이 목표입니다.  
1차 목표는 단일 기타나 기타가 뚜렷하게 들리는 음원에 대해 `result.mid`와 `result_tab.txt`를 생성하는 것입니다.  
반면 벤딩, 슬라이드, 비브라토의 고정밀 표기나 라이브 음원 복원 같은 부분은 초기 범위에서 제외했습니다.

## 4번 슬라이드

이 슬라이드는 전체 처리 흐름입니다.  
먼저 오디오 파일을 업로드하면 입력 검증과 전처리를 거칩니다.  
필요하면 기타 분리 단계를 수행하고, 이후 onset 검출과 pitch 추정을 통해 note event를 생성합니다.  
그 다음 quantization으로 박자를 정렬하고, 마지막으로 줄과 프렛을 매핑해서 MIDI와 탭 파일을 출력합니다.  

## 5번 슬라이드

이 슬라이드는 사용자가 실제로 이용하게 되는 주요 기능을 정리한 것입니다.  
먼저 파일 업로드와 분석 시작 기능이 있습니다.  
사용자는 음원을 선택한 뒤 바로 분석을 실행할 수 있습니다.  
그 다음 처리 상태 확인 기능을 통해 현재 분석이 어느 정도 진행되고 있는지 확인할 수 있습니다.  
분석이 끝나면 결과 화면에서 원본 음원과 기타 분리 음원을 재생할 수 있고, MIDI 파일을 다운로드할 수 있습니다.  
또 탭 보기를 통해 생성된 기타 탭 초안을 확인할 수 있고, 필요하면 다시 새로운 파일을 분석할 수도 있습니다.  

## 6번 슬라이드

화면 구성입니다.  
첫 번째 화면은 메인 업로드 화면입니다.  
사용자는 드래그 앤 드롭이나 클릭으로 파일을 선택할 수 있고, 샘플 파일을 불러올 수도 있습니다.  
분석 시작 버튼을 누르면 다음 화면으로 이동합니다.  

## 7번 슬라이드

두 번째 화면은 처리 상태 화면입니다.  
이 화면에서는 분석 중이라는 점을 스피너와 단계 표시로 보여줍니다.  
예를 들어 파일 확인 완료, 오디오 분석 완료, 탭 생성 중, 결과 준비 중처럼 현재 어느 단계인지 확인할 수 있습니다.  
사용자는 내부 알고리즘을 몰라도, 지금 시스템이 정상적으로 진행 중이라는 사실을 직관적으로 알 수 있습니다.

## 8번 슬라이드

세 번째 화면은 분석 결과 화면입니다.  
여기서 사용자는 원본 음원과 기타 분리 음원을 재생할 수 있고, MIDI 파일을 다운로드할 수 있습니다.  
또 생성된 ASCII 탭을 미리보고, 필요하면 탭 상세 화면으로 이동할 수 있습니다.  

## 9번 슬라이드

이 슬라이드는 화면 간 상호관계입니다.  
메인 업로드 화면에서 분석을 시작하면 처리 상태 화면으로 이동하고,  
처리가 끝나면 결과 화면으로 넘어갑니다.  
결과 화면에서 탭을 더 자세히 보고 싶으면 탭 상세 보기 화면으로 이동합니다.  
또 결과 화면에서 다시 새 파일 분석으로 돌아갈 수 있도록 흐름을 구성했습니다.

## 10번 슬라이드

마지막으로 이번 주 진행 내용과 다음 주 계획입니다.  
이번 주에는 사용자 관점에서 실제 서비스처럼 보이는 프론트 화면을 구현했습니다.  
업로드 화면, 처리 상태 화면, 결과 화면, 탭 상세 화면을 구성했고, 화면 간 흐름도 자연스럽게 연결되도록 정리했습니다.    
다음 주에는 이 프론트 화면과 실제 업로드 기능을 연결할 수 있도록 백엔드 초기 구조를 만들 예정입니다.
