# 기본틀

# 1. 프로젝트 목표 정의

## 최종 목표

입력:

- mp3 / wav 녹음파일

출력:

- 기타 분리 음원
- MIDI 파일
- 기타 탭 초안
- 선택적으로 오선보 또는 MusicXML

## 핵심 기능

1. 오디오 업로드
2. 기타 성분 분리
3. 음 시작 시점(onset) 검출
4. 음 높이(pitch) 추정
5. 음 길이(duration) 추정
6. 기타 줄/프렛 매핑
7. 탭 및 MIDI 생성
8. 결과 미리보기

---

# 2. 전체 시스템 구조

가장 현실적인 구조는 **3단계 파이프라인**이다.

## 1단계: 기타 분리

혼합 음원에서 기타가 포함된 성분만 최대한 남긴다.

- 입력: 전체 녹음
- 출력: `guitar_separated.wav`

이 단계에서는 **완벽하게 기타만 분리**하는 것이 아니라,

**“채보에 쓸 수 있을 정도로 기타를 강조”**하는 것이 목표다.

Demucs는 음악 소스 분리용으로 널리 쓰이는 모델이며, 보컬/드럼/베이스/기타를 포함한 반주 분리에 사용된다. 공식 저장소는 v4에서 하이브리드 스펙트로그램·웨이브폼 구조와 Transformer 기반 구성을 설명한다.

---

## 2단계: 기타 자동 채보

분리된 기타 음원에서 음표 정보를 추출한다.

- onset detection
- pitch detection
- polyphonic note detection
- note duration estimation

librosa는 음악·오디오 분석용 파이썬 패키지이며, onset detection과 같은 MIR 기본 구성요소를 제공한다. torchaudio는 spectrogram, melspectrogram 같은 변환을 제공하고 CPU/CUDA에서 사용할 수 있다.

---

## 3단계: 기타 탭 생성

검출된 음들을 기타 연주자가 읽을 수 있는 형태로 바꾼다.

- MIDI 생성
- MusicXML 생성
- Tab ASCII 또는 웹 표시
- 줄/프렛 자동 배치

pretty_midi는 MIDI를 다루기 쉽게 만드는 파이썬 라이브러리이고, music21은 MIDI와 MusicXML의 import/export를 지원한다.

---

# 3. 졸업작품 범위에서 추천하는 현실적 목표

처음부터 “아무 밴드 음악이나 넣으면 완벽한 기타 탭 생성”은 범위가 너무 크다.

그래서 목표를 이렇게 잡는 게 좋다.

## 1차 목표

**단일 기타 연주 녹음 → MIDI + Tab 생성**

예:

- 통기타 멜로디
- 일렉기타 리프
- 반주 거의 없는 연주

이건 구현 가능성이 높다.

## 2차 목표

**혼합 음원 → 기타 분리 → MIDI + Tab 생성**

이건 분리 오차 때문에 더 어렵지만, 졸업작품 데모로는 매우 좋다.

## 제외하거나 축소할 기능

초기 버전에서는 아래는 욕심내지 않는 게 좋다.

- 벤딩 정확 인식
- 슬라이드/비브라토 완벽 표기
- 복잡한 재즈 화음 완전 채보
- 드럼/보컬 섞인 라이브 음원에서 고정밀 결과
- 드롭 튜닝 자동 추정

# 5. 모듈별 상세 설계

## A. 입력/전처리 모듈

### 역할

- mp3/wav 업로드
- 샘플레이트 통일
- mono/stereo 정리
- 길이 제한
- 노멀라이즈

### 추천 처리

- 샘플레이트: 22050Hz 또는 44100Hz
- 파일 길이: 초기에는 30초~1분 제한
- 너무 긴 파일은 자르기

### 출력

- `input.wav`

---

## B. 기타 분리 모듈

### 방법 1: 기존 모델 활용

가장 추천한다.

- Demucs 계열 모델 사용
- 출력 stem 중 guitar 또는 other stem 활용
- 기타가 약하면 후처리로 EQ/노이즈 억제 추가

### 왜 이게 좋은가

- 처음부터 분리 모델 재학습 안 해도 됨
- 결과가 바로 나옴
- 시연하기 좋음

### 한계

- 곡에 따라 기타가 other stem에 섞일 수 있음
- 깨끗하지 않을 수 있음

### 출력

- `guitar_separated.wav`

---

## C. 채보 모듈

이 부분이 프로젝트 핵심이다.

### 1. Onset detection

음이 시작되는 지점을 찾는다.

librosa의 onset detection은 onset strength envelope의 피크를 기반으로 음 시작 지점을 찾는다.

출력 예:

```
[
0.42,
0.88,
1.31
]
```

---

### 2. Pitch detection

각 구간에서 어떤 음이 울리는지 추정한다.

여기서 선택지는 2가지다.

### 방법 A. 기본 신호처리 기반

- STFT / CQT
- 주파수 피크 탐색
- 배음 패턴 분석

장점:

- 직접 구현 설명이 쉬움
- 푸리에 변환을 프로젝트 핵심으로 넣기 좋음

단점:

- 화음이나 잡음에 약함

### 방법 B. 기존 AMT 모델 활용

Spotify의 Basic Pitch는 가벼운 자동 음악 채보(AMT) 라이브러리이며, pitch bend 검출도 지원한다. 공식 소개에서는 “almost any instrument”에 대해 audio-to-MIDI를 지원하고, 다성음(polyphonic) 처리도 가능하다고 설명한다.

장점:

- 정확도가 더 좋을 수 있음
- MIDI 생성이 쉬움

단점:

- 내부를 완전히 네가 구현한 것은 아님

### 추천

졸업작품에서는 **둘 다 쓰는 방식**이 좋다.

- 기본 버전: STFT/CQT 기반 피치 추정
- 향상 버전: Basic Pitch로 보정

이렇게 하면 발표할 때

**“푸리에 기반 1차 분석 + 딥러닝 보정”**

구조로 설명할 수 있다.

---

### 3. Note event 생성

온셋과 피치를 합쳐 음표 이벤트로 만든다.

예:

```
[
  {"start":0.42, "end":0.74, "pitch":64},
  {"start":0.88, "end":1.10, "pitch":67}
]
```

여기서 `pitch`는 MIDI note number다.

---

### 4. Quantization

실제 연주는 박자에 딱 맞지 않으므로 적절히 정렬해야 한다.

예:

- 0.49초 → 8분음표 시작
- 1.01초 → 다음 박 위치로 보정

이 단계가 있어야 사람이 읽을 수 있는 악보가 된다.

---

## D. 줄/프렛 매핑 모듈

이게 기타 탭에서 매우 중요하다.

같은 음도 여러 위치로 칠 수 있다.

예를 들어 E4는:

- 1번줄 0프렛
- 2번줄 5프렛
- 3번줄 9프렛

그래서 시스템은 **음이름만 찾는 게 아니라 최적 운지를 추정**해야 한다.

### 기본 규칙

1. 가능한 낮은 포지션 우선
2. 직전 음과 손 이동 최소화
3. 같은 프레이즈는 비슷한 위치 유지
4. 열린 줄 사용을 어느 정도 허용
5. 너무 비현실적인 점프는 패널티 부여

### 구현 방식

각 음표마다 가능한 후보를 나열한다.

예:

```
E4 -> [(1번줄,0프렛), (2번줄,5프렛), (3번줄,9프렛)]
```

그 다음 연속된 음들에 대해 비용을 계산한다.

비용 예:

- 프렛 이동 거리
- 줄 이동 수
- 포지션 급변 여부
- 손가락 뻗기 난이도

그리고 **동적 계획법(DP)** 으로 전체 비용이 최소가 되는 경로를 고른다.

이 방식은 설명도 좋고 구현도 가능하다.

## E. 출력 모듈

## 1. MIDI 출력

가장 먼저 구현하는 것을 추천한다.

pretty_midi는 MIDI 파일 생성과 분석을 쉽게 해준다.

장점:

- 구현 쉬움
- DAW에서 바로 열어볼 수 있음
- 성능 평가에 좋음

---

## 2. MusicXML 출력

music21은 MIDI와 MusicXML을 다룰 수 있다.

장점:

- MuseScore 같은 악보 프로그램과 연동 쉬움
- 오선보 출력 가능

---

## 3. Tab 출력

초기 버전은 ASCII tab만 해도 충분하다.

예:

```
e|----------------|
B|----------------|
G|------2---------|
D|----2---2-------|
A|--0-------------|
E|----------------|
```

웹에서는 이것을 좀 더 보기 좋게 렌더링하면 된다.

# 9. 평가 방법

졸업작품이면 “잘 된다”보다 **어떻게 평가했는지**가 중요하다.

## 분리 성능 평가

- 원본 대비 청취 평가
- 기타가 얼마나 잘 들리는지 주관 평가
- 가능하면 SDR/SIR/SAR 같은 분리 지표

## 채보 성능 평가

- note precision
- note recall
- F1 score
- onset 오차
- pitch 정확도

## 탭 품질 평가

- 실제 연주자가 봤을 때 자연스러운지
- 손 이동이 과도하지 않은지
- 사람이 수정하기 쉬운 초안인지

# 10. 발표 때 강조하면 좋은 포인트

이 프로젝트는 발표 구조가 좋다.

## 문제 정의

기타 연주자는 녹음을 듣고 직접 채보하는 데 시간이 많이 든다.

## 해결 아이디어

AI와 신호처리를 결합해 자동으로 기타 음원을 분리하고 탭 초안을 생성한다.

## 기술 핵심

- 푸리에 변환 기반 주파수 분석
- 소스 분리 모델
- onset/pitch 추정
- 기타 운지 최적화

## 차별점

단순 audio-to-MIDI가 아니라,

**기타 연주자를 위한 줄/프렛 기반 탭 생성**까지 수행한다.

# 11. 현실적인 최종 목표 문장

논문/제안서 스타일로 쓰면 이렇게 정리할 수 있다.

**본 시스템은 입력된 녹음 파일로부터 기타 성분을 분리한 뒤, 시간-주파수 분석과 자동 채보 기법을 이용하여 음표 이벤트를 추출하고, 이를 기타 줄/프렛 위치로 매핑하여 MIDI 및 탭 악보 초안을 자동 생성하는 것을 목표로 한다.**
