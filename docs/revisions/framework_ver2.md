# 프로젝트 프레임워크 Ver2

## 1. 프로젝트 개요

### 목표

본 프로젝트의 목표는 녹음 파일에서 기타 연주 정보를 추출하여 다음 결과물을 자동 생성하는 것이다.

- 기타 강조 음원
- MIDI 파일
- 기타 탭 초안
- 선택적 MusicXML 또는 오선보 초안

### 입력과 출력

입력:

- `mp3`, `wav` 오디오 파일

출력:

- `guitar_separated.wav`
- `result.mid`
- `result_tab.txt`
- 선택적 `result.musicxml`

### 핵심 가치

- 사람이 수작업으로 하던 기타 채보 시간을 줄인다.
- 완성본이 아니라 수정 가능한 초안을 빠르게 만든다.
- 단순 audio-to-MIDI가 아니라 기타 줄/프렛 정보까지 제공한다.

---

## 2. 범위 정의

### MVP 범위

우선 구현 범위는 다음으로 제한한다.

- 단일 기타 또는 기타가 지배적인 짧은 음원 입력
- 60초 이하 파일 처리
- onset, pitch, duration 기반 note event 생성
- note event를 줄/프렛으로 매핑
- MIDI와 ASCII 탭 출력

### 확장 범위

MVP 이후 확장 목표는 다음과 같다.

- 혼합 음원에서 기타 성분 분리
- MusicXML 생성
- 웹 업로드 및 결과 미리보기
- 분리/채보 성능 평가 자동화

### 제외 범위

초기 버전에서는 다음을 목표에서 제외한다.

- 벤딩, 슬라이드, 비브라토의 고정밀 표기
- 드롭 튜닝 자동 추정
- 라이브 공연 녹음의 고정밀 복원
- 복잡한 재즈 화음 완전 채보
- 모든 장르와 모든 악기 조합에 대한 일반화

## 3. 전체 시스템 구조

가장 현실적인 구조는 3단계 파이프라인이다.

### 1단계. 오디오 전처리 및 기타 분리

역할:

- 입력 파일 검증
- 샘플레이트 통일
- mono/stereo 처리
- 길이 제한 적용
- 필요 시 기타 성분 분리

입력:

- 원본 오디오 파일

출력:

- `input.wav`
- 선택적 `guitar_separated.wav`

설계 원칙:

- 분리는 필수 단계가 아니라 확장 단계로 둔다.
- 채보에 쓸 수 있을 만큼 기타를 강조하는 것이 목표다.

### 2단계. 기타 자동 채보

역할:

- onset detection
- pitch detection
- note duration 추정
- note event 생성
- quantization

입력:

- `input.wav` 또는 `guitar_separated.wav`

출력:

- note event list

예시:

```json
[
  { "start": 0.42, "end": 0.74, "pitch": 64 },
  { "start": 0.88, "end": 1.10, "pitch": 67 }
]
```

### 3단계. 탭 및 파일 생성

역할:

- 줄/프렛 후보 생성
- 운지 비용 계산
- 최적 경로 선택
- MIDI, MusicXML, ASCII 탭 생성

입력:

- quantized note events

출력:

- `result.mid`
- `result_tab.txt`
- 선택적 `result.musicxml`

## 5. 모듈 설계

### A. 입력 및 전처리 모듈

책임:

- 파일 포맷 검사
- 디코딩 실패 처리
- 샘플레이트를 `22050Hz` 또는 `44100Hz`로 통일
- 최대 길이 `60초` 제한
- 분석용 내부 포맷으로 변환

성공 기준:

- 지원 포맷 파일이 안정적으로 `input.wav`로 변환된다.
- 잘못된 파일은 명확한 오류 메시지를 반환한다.

### B. 기타 분리 모듈

기본 접근:

- Demucs 계열 모델 사용
- `guitar` stem 우선 사용
- 필요 시 `other` stem fallback 허용

성공 기준:

- 혼합 음원에서 기타 성분이 채보 가능한 수준으로 강조된다.

리스크:

- 곡에 따라 기타가 다른 stem에 섞일 수 있다.
- 분리 오류가 이후 pitch 검출 정확도를 낮출 수 있다.

### C. 채보 모듈

구성:

- onset detection
- pitch detection
- note event 생성
- quantization

추천 구현 전략:

- 기본 버전: STFT/CQT 기반 추정
- 향상 버전: Basic Pitch 같은 사전학습 모델로 보정

설계 이유:

- 발표 시 신호처리 기반 접근을 설명하기 쉽다.
- 실제 정확도는 사전학습 모델 보정으로 끌어올릴 수 있다.

### D. 줄/프렛 매핑 모듈

핵심 아이디어:

- 같은 pitch가 여러 줄/프렛 위치에 존재하므로 운지 최적화가 필요하다.

기본 규칙:

1. 낮은 포지션을 우선한다.
2. 직전 음과의 이동 거리를 최소화한다.
3. 같은 프레이즈에서는 비슷한 포지션을 유지한다.
4. 열린 줄 사용은 허용하되 과도한 점프에는 패널티를 준다.

구현 방식:

1. 각 note에 대해 가능한 줄/프렛 후보 생성
2. 후보 간 전이 비용 계산
3. 동적 계획법으로 최소 비용 경로 선택

### E. 출력 모듈

우선순위:

1. MIDI
2. ASCII 탭
3. MusicXML

이유:

- MIDI는 검증과 재생이 가장 쉽다.
- ASCII 탭은 구현이 단순하고 데모에 적합하다.
- MusicXML은 후속 단계에서 악보 프로그램 연동에 유리하다.

## 7. 개발 로드맵

### 1단계. 최소 기능 제품

목표:

- 단일 기타 입력
- onset + pitch 추출
- note event 생성
- MIDI 출력

완료 기준:

- 단순 멜로디가 재생 가능한 MIDI로 변환된다.

### 2단계. 탭 생성

목표:

- 줄/프렛 매핑
- ASCII 탭 생성

완료 기준:

- 단순 리프가 사람이 읽을 수 있는 탭으로 출력된다.

### 3단계. 혼합 음원 지원

목표:

- 기타 분리
- 분리 결과를 채보 파이프라인에 연결

완료 기준:

- 반주가 섞인 일부 테스트 음원에서 초안 결과가 생성된다.

### 4단계. 웹 시연

목표:

- 파일 업로드
- 처리 진행 상태 표시
- 결과 재생 및 다운로드

완료 기준:

- 심사 또는 데모 상황에서 직접 시연 가능하다.

## 8. 평가 방법

### 분리 성능

- 주관 청취 평가
- 가능하면 SDR, SIR, SAR 측정

### 채보 성능

- onset 오차
- pitch accuracy
- note precision / recall / F1

### 탭 품질

- 실제 연주 가능성
- 손 이동의 자연스러움
- 사람이 후편집하기 쉬운지 여부

---

## 9. 발표용 핵심 메시지

- 문제: 기타 채보는 수작업 비용이 크다.
- 해결: 신호처리와 AI를 결합해 자동으로 기타 연주 초안을 생성한다.
- 차별점: 단순 MIDI 변환이 아니라 기타 줄/프렛 기반 탭까지 출력한다.

---

## 10. 최종 목표 문장

본 시스템은 입력된 녹음 파일로부터 기타 연주 정보를 추출하고, 이를 note event와 줄/프렛 위치로 변환하여 MIDI 및 기타 탭 초안을 자동 생성하는 것을 목표로 한다.
