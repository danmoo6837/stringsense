# 기능 명세서 Ver2

## 1. 문서 목적

이 문서는 자동 기타 채보 시스템의 기능 요구사항과 비기능 요구사항을 구현 가능한 수준으로 정리한다.

---

## 2. 시스템 개요

본 시스템은 입력된 오디오 파일을 분석하여 기타 음표 이벤트를 추출하고, 이를 MIDI 및 기타 탭 형태로 반환한다.

기본 모드:

- 단일 기타 또는 기타가 지배적인 오디오 입력

확장 모드:

- 혼합 음원에서 기타 분리 후 채보

---

## 3. 기능 요구사항

## [F1] 오디오 업로드 및 전처리

### 목적

분석 가능한 내부 오디오 포맷으로 입력 파일을 변환한다.

### 입력

- `mp3`, `wav`

### 처리

- 포맷 검증
- 오디오 디코딩
- 샘플레이트 통일: `22050Hz` 또는 `44100Hz`
- 채널 처리: mono 기준으로 변환
- 길이 제한: 최대 `60초`
- 내부 파일명 `input.wav`로 저장

### 출력

- `input.wav`

### 예외 처리

- 지원하지 않는 포맷: `400 Bad Request`
- 파일 손상 또는 디코딩 실패: 처리 중단
- 길이 초과: 업로드 거부 또는 앞 `60초`만 사용

### 테스트 기준

- 정상 `wav` 업로드 시 `input.wav` 생성
- 정상 `mp3` 업로드 시 `input.wav` 생성
- 손상 파일 업로드 시 명확한 오류 반환

---

## [F2] 기타 음원 분리

### 목적

혼합 음원에서 기타 성분을 최대한 강조한 오디오를 생성한다.

### 입력

- `input.wav`

### 처리

- Demucs 기반 소스 분리
- `guitar` stem 우선 선택
- 필요 시 `other` stem fallback
- 선택적 후처리: gain 조정, 노이즈 억제

### 출력

- `guitar_separated.wav`

### 예외 처리

- 모델 로드 실패: 분리 기능 비활성화 또는 오류 반환
- GPU 미사용 환경: CPU 모드로 수행하되 처리 시간 증가 허용

### 성능 기준

- 테스트 혼합 음원에서 기타가 청취 가능해야 한다.
- 60초 파일 기준 목표 처리 시간은 별도 환경 명세에서 측정한다.

---

## [F3] Onset Detection

### 목적

기타 음의 시작 시점을 검출한다.

### 입력

- `input.wav` 또는 `guitar_separated.wav`

### 처리

- onset strength 계산
- peak detection
- 매우 가까운 중복 onset 제거

### 출력

```json
[0.42, 0.88, 1.31]
```

### 예외 처리

- 무음 구간이 긴 경우 빈 배열 허용

### 테스트 기준

- 단일 음 반복 샘플에서 실제 onset과 유사한 위치를 반환

---

## [F4] Pitch Detection

### 목적

각 구간에서 발생한 음의 pitch를 추정한다.

### 입력

- `input.wav` 또는 `guitar_separated.wav`
- onset 정보

### 처리

- 방법 A: STFT/CQT 기반 추정
- 방법 B: 사전학습 모델 기반 추정
- 선택한 전략에 따라 결과 병합 또는 단일 결과 채택

### 출력

- MIDI note number 리스트 또는 구간별 pitch 정보

### 예외 처리

- 신뢰도가 낮은 구간은 `unknown` 또는 낮은 confidence로 표시 가능

### 테스트 기준

- 단일 음 샘플에서 목표 음과 근접한 MIDI note 반환

---

## [F5] Note Event 생성

### 목적

onset, offset, pitch 정보를 결합하여 note event를 생성한다.

### 입력

- onset list
- pitch 결과
- duration 또는 offset 추정값

### 처리

- onset 단위 구간화
- 구간별 대표 pitch 선택
- `start`, `end`, `pitch`, 선택적 `confidence` 구성

### 출력

```json
[
  { "start": 0.42, "end": 0.74, "pitch": 64, "confidence": 0.91 },
  { "start": 0.88, "end": 1.10, "pitch": 67, "confidence": 0.87 }
]
```

### 테스트 기준

- note event가 시간 순서대로 정렬되어야 한다.
- `end`는 항상 `start`보다 커야 한다.

---

## [F6] Quantization

### 목적

사람의 연주 타이밍을 읽기 쉬운 박자 단위로 정렬한다.

### 입력

- note events

### 처리

- BPM 추정
- beat grid 생성
- nearest grid 또는 규칙 기반 snap

### 출력

- quantized note events

### 예외 처리

- BPM 추정 실패 시 quantization 생략 가능

### 테스트 기준

- 양자화 후 note event 순서가 깨지지 않아야 한다.
- 과도한 음 길이 왜곡이 없어야 한다.

---

## [F7] 줄/프렛 매핑

### 목적

MIDI 음을 실제 기타 연주 가능한 줄/프렛 위치로 변환한다.

### 입력

- quantized note events
- 표준 튜닝 정보

### 처리

1. 각 pitch의 가능한 줄/프렛 후보 생성
2. 전이 비용 계산
3. 동적 계획법으로 최소 비용 경로 선택

비용 요소:

- 프렛 이동 거리
- 줄 이동량
- 포지션 유지
- 과도한 점프 패널티
- 열린 줄 선호도

### 출력

```json
[
  { "pitch": 64, "string": 1, "fret": 0 },
  { "pitch": 47, "string": 5, "fret": 2 }
]
```

### 예외 처리

- 표준 튜닝 범위를 벗어나는 음은 매핑 실패로 표시

### 테스트 기준

- 동일 pitch에 대해 복수 후보 중 일관된 위치를 선택해야 한다.
- 사람에게 명백히 비현실적인 점프는 최대한 피해야 한다.

---

## [F8] MIDI 생성

### 목적

note events를 재생 가능한 MIDI 파일로 변환한다.

### 입력

- note events 또는 quantized note events

### 처리

- tempo 설정
- MIDI note 생성
- 파일 저장

### 출력

- `result.mid`

### 테스트 기준

- 일반 MIDI 플레이어 또는 DAW에서 정상 재생

---

## [F9] 탭 생성

### 목적

줄/프렛 정보를 사람이 읽을 수 있는 탭 형식으로 출력한다.

### 입력

- 줄/프렛 매핑 결과

### 처리

- 문자열 정렬
- 시간 순서 반영
- ASCII 탭 렌더링

### 출력

- `result_tab.txt`

예시:

```text
e|----------------|
B|----------------|
G|------2---------|
D|----2---2-------|
A|--0-------------|
E|----------------|
```

### 테스트 기준

- 6줄 구조를 유지해야 한다.
- 프렛 숫자가 음 순서를 깨뜨리지 않아야 한다.

---

## [F10] 결과 반환 및 시각화

### 목적

사용자가 결과를 확인하고 다운로드할 수 있게 한다.

### 입력

- 생성된 결과 파일

### 처리

- 기타 분리 음원 재생 링크 제공
- MIDI 다운로드 제공
- 탭 텍스트 표시
- 선택적 악보 렌더링

### 출력

- 웹 또는 로컬 파일 기반 결과 화면

### 선택 기술

- 웹 악보 렌더링: VexFlow
- PDF 악보 생성: LilyPond 또는 MusicXML 기반 도구

---

## 4. 비기능 요구사항

### N1. 처리 시간

- 목표: 60초 입력 파일 기준 `30초 이내`
- 측정 조건은 CPU/GPU, 모델 종류와 함께 별도 기록해야 한다.

### N2. 정확도

- 단일 기타 입력에서 onset과 pitch가 데모 가능한 수준으로 동작해야 한다.
- 혼합 음원 모드는 MVP 이후 확장 기능으로 본다.

### N3. 안정성

- 잘못된 파일 입력 시 시스템이 중단되지 않아야 한다.
- 개별 단계 실패 시 원인을 로그로 남겨야 한다.

### N4. 재현성

- 같은 입력과 같은 설정이면 동일하거나 매우 유사한 결과를 재현해야 한다.

### N5. 사용성

- 사용자는 파일 업로드 후 결과 파일을 쉽게 확인하고 다운로드할 수 있어야 한다.

---

## 5. MVP 승인 기준

다음을 만족하면 MVP를 완료한 것으로 본다.

1. 60초 이하 단일 기타 입력을 처리할 수 있다.
2. `result.mid`가 정상 생성된다.
3. `result_tab.txt`가 정상 생성된다.
4. 최소 3개 이상의 테스트 샘플에서 데모 가능한 결과가 나온다.
